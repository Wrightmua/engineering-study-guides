Q1.1

Five Types of Embedded Systems

5 × 1 mark

Classification depends on what angle you look from — function, timing, connectivity, or scale. Examiners want the name and one line on why it fits that name.

① Standalone

Works independently — takes input, processes it, produces output, with no host computer needed.

  • Example: a digital microwave timer, a calculator

② Real-Time

Output correctness depends on meeting a timing deadline, not just producing the right value.

  • Example: anti-lock braking system

③ Networked

Connects to a network (wired or wireless) to share data or accept commands remotely.

  • Example: your ESP32 traffic dashboard over Wi-Fi

④ Mobile

Small, portable, battery-powered — optimized for size and power draw over raw performance.

  • Example: smartwatch, fitness tracker

⑤ Small-scale / Large-scale

Classified by hardware complexity — 8/16-bit MCU with few peripherals vs. 32/64-bit multi-core with many.

  • Example: a doorbell chip (small) vs. a car ECU (large)
Q1.2

Real-Time Embedded Systems

1+1+1 marks

A Real-Time Embedded System (RTES) must produce correct output within a strict, predictable time window — being late is treated the same as being wrong. The exam wants you to split this into soft vs. hard, with two examples each.

Soft Real-Time tolerable delay

Missing the deadline degrades quality of service, but the system still works and no serious harm occurs.

  • Video/audio streaming — a late frame just looks like a glitch
  • Your ESP32 web dashboard updating traffic light status — a slightly delayed refresh is annoying, not dangerous

Hard Real-Time zero tolerance

Missing the deadline is a total system failure — it can cause damage, injury, or loss of life.

  • Airbag deployment controller
  • Pacemaker / medical infusion pump
Q1.3

RTOS vs. GPOS

2.5 marks

RTOS (Real-Time Operating System): an OS built to guarantee that a task completes within a bounded, predictable time using deterministic, priority-based scheduling.

DimensionRTOSGPOS (e.g. Windows/Linux desktop)
GoalPredictability / determinismAverage throughput & fairness
SchedulingPriority-based, preemptiveTime-sharing, best-effort
Response timeBounded & guaranteedVariable, not guaranteed
FootprintMinimal — runs on constrained MCUsLarge — needs significant RAM/storage
Failure modeA missed deadline = system failure (hard RT)A slow response is just inconvenient

Embedded AI

3 marks

Embedded AI is the integration of AI/ML models directly into resource-constrained devices, so inference happens locally on-device rather than being sent to the cloud.

TPU

Tensor Processing Unit — accelerates the matrix multiplications behind neural network inference.

NPU

Neural Processing Unit — a dedicated core for AI workloads, found in newer chips like the ESP32-S3.

GPU

Graphics Processing Unit — massively parallel, reused for AI math on more powerful embedded boards.

Q1.6

Round Robin Scheduling

4 marks

Click through the ticks below — this is exactly how an examiner expects you to narrate it.

  • Every task waits in a circular queue and is given a fixed time quantum (slice)
  • The CPU runs the task at the front of the queue until the quantum expires — or the task finishes early
  • If the quantum expires and the task isn't done, it's preempted and sent to the back of the queue
  • The next task in line then gets its turn — no task can monopolize the CPU
  • This repeats continuously, giving every task fair, predictable access to processing time

Q2.3

Labeled Circuit Diagram

15 marks

Full wiring diagram for the 4-way intersection: each traffic light module (R/Y/G LEDs + 330Ω resistors) on its own GPIO trio, four push buttons on pull-down inputs for manual override, and shared power/ground rails. Reproduce this structure — labeled pins, resistor values, and the pull-down convention — for full marks.

Why this wiring works

  • Each light module uses 3 GPIOs (Red/Yellow/Green) — 4 modules × 3 pins = 12 output pins total
  • Each push button uses 1 GPIO input with a pull-down resistor, so the pin reads a defined LOW when not pressed and HIGH when pressed
  • All LED cathodes and button pull-downs share a common GND rail back to the ESP32
  • 330Ω resistors in series with every LED protect against excess current from the 3.3V GPIO logic level

Q3.1

Reading the Relay Code

10 marks

Click each highlighted line below to reveal what the examiner wants you to say about it.

const int relay = 26;
void setup() {
  Serial.begin(115200);
  pinMode(relay, OUTPUT);
}
void loop() {
  digitalWrite(relay, LOW);
  Serial.println("Current Flowing");
  delay(5000);
  digitalWrite(relay, HIGH);
  Serial.println("Current not Flowing");
  delay(5000);
}
const int relay = 26;Assigns GPIO 26 as the pin controlling the relay module. Serial.begin(115200);Opens serial communication at 115200 baud for debug output on the monitor. pinMode(relay, OUTPUT);Configures GPIO 26 as a digital output pin. digitalWrite(relay, LOW);Drives GPIO 26 LOW — for a LOW-triggered relay module, this energizes the coil (relay ON). Serial.println("Current Flowing");Logs the ON state to the serial monitor. delay(5000);Holds the current state for 5 seconds (blocking delay). digitalWrite(relay, HIGH);Drives GPIO 26 HIGH — de-energizes the relay coil (relay OFF).

Overall function

The program toggles a relay ON and OFF every 5 seconds in an infinite loop, simulating a load switching on/off repeatedly while logging each transition to the serial monitor. Note this is a LOW-triggered relay — a common module type where LOW = energized, which is worth stating explicitly since it's an easy mark to miss.

Q3.2

WiFi Access Point Setup

10 marks

Setting up the ESP32 as its own Access Point (BSS) so a phone/laptop can connect directly to it — the same pattern your traffic dashboard's AP fallback uses.

#include <WiFi.h>

const char* ssid = "ESP32_Traffic_AP";
const char* password = "12345678";

void setup() {
  Serial.begin(115200);
  WiFi.softAP(ssid, password);      // sets up the BSS credentials
  IPAddress IP = WiFi.softAPIP();
  Serial.print("AP IP address: ");
  Serial.println(IP);              // prints IP to serial monitor
}

void loop() {
}

Why this earns full marks

WiFi.softAP() is the exact call that establishes the Basic Service Set (BSS) — the SSID + password pair — turning the ESP32 into its own access point rather than joining an existing network. softAPIP() retrieves the IP address assigned to that AP so a client device knows where to connect.
