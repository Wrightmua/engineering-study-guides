Conversion Rules

Any Base → Decimal (Positional Notation)

Multiply each digit by its positional weight (base^position) and sum.

(11101.1011)₂ → Decimal
= 1×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰ + 1×2⁻¹ + 0×2⁻² + 1×2⁻³ + 1×2⁻⁴
= 16 + 8 + 4 + 0 + 1 + 0.5 + 0 + 0.125 + 0.0625
= 29.6875

(EF9.B)₁₆ → Decimal
= 14×16² + 15×16¹ + 9×16⁰ + 11×16⁻¹
= 3584 + 240 + 9 + 0.6875 = 3833.6875

Decimal Integer → Any Base (Repeated Division)

Divide by the target base repeatedly. Remainders, read bottom-to-top, give the result.

(57)₁₀ → Binary:
57 ÷ 2 = 28 remainder 1 ← LSB
28 ÷ 2 = 14 remainder 0
14 ÷ 2 = 7 remainder 0
7 ÷ 2 = 3 remainder 1
3 ÷ 2 = 1 remainder 1
1 ÷ 2 = 0 remainder 1 ← MSB
Result (read upward): (111001)₂

Decimal Fraction → Any Base (Repeated Multiplication)

Multiply by the base, collect the integer parts top-to-bottom.

(0.79425)₁₀ → Binary:
0.79425 × 2 = 1.5885 → 1
0.5885 × 2 = 1.177 → 1
0.177 × 2 = 0.354 → 0
0.354 × 2 = 0.708 → 0
0.708 × 2 = 1.416 → 1
Result: (0.11001...)₂

Complements

One's Complement

Flip every bit (0→1, 1→0).

1000001 → 0111110
0.0101 → 1.1010
101001.0100→010110.1011

Two's Complement

One's complement + 1.

1111110000:
1's: 0000001111
+1: 0000010000

0.010100:
1's: 1.101011
+1: 1.101100
Shortcut for 2's Complement: Start from the LSB; copy bits up to and including the first 1, then flip all remaining bits.

Computer Codes

BCD (Binary Coded Decimal)

Each decimal digit is encoded separately into 4-bit binary.

(674.027)₁₀ in BCD:
6 = 0110
7 = 0111
4 = 0100
. = .
0 = 0000
2 = 0010
7 = 0111
BCD = 0110 0111 0100 . 0000 0010 0111
⚠ Note: BCD digits only go 0000–1001 (0–9). Codes 1010–1111 are invalid in BCD.

Excess-3 Code

Excess-3 = BCD + 0011. Also called XS-3. Self-complementing code.

(674.027)₁₀ in Excess-3:
6+3=9 → 1001
7+3=10→ 1010
4+3=7 → 0111
0+3=3 → 0011
2+3=5 → 0101
7+3=10→ 1010

Gray Code

Adjacent values differ by exactly 1 bit. Used to avoid errors in mechanical encoders.

Decimal/Binary → Gray

MSB of Gray = MSB of Binary
Each next Gray bit = XOR of that Binary bit with the previous Binary bit

Binary: 1 0 0 1
Gray: 1 (1⊕0)=1 (0⊕0)=0 (0⊕1)=1 → 1101

Gray → Binary

1. MSB of Binary = MSB of Gray
2. Each Binary bit = XOR of current Gray bit with PREVIOUS Binary bit

Gray: 1 1 1 0 1 0 1 1
Binary: 1(1⊕1)=0(1⊕0)=1(0⊕1)=1(0⊕1)=0(1⊕0)=1(1⊕1)=0 = 10110010

Boolean Laws & Theorems

Basic Laws

Commutative: A+B = B+A AB = BA Associative: A+(B+C) = (A+B)+C A(BC) = (AB)C Distributive: A(B+C) = AB+AC A+BC = (A+B)(A+C)

Identity / Null / Complement

Identity: A+0 = A, A·1 = A Null: A+1 = 1, A·0 = 0 Complement: A+Ā = 1, A·Ā = 0 Idempotent: A+A = A, A·A = A Involution: Ā̄ = A (double complement)

DeMorgan's Theorems (⭐ Very Important)

‾(AB) = Ā + B̄    (NAND = OR with inverted inputs)
‾(A+B) = Ā · B̄   (NOR = AND with inverted inputs)
Memory trick: Break the bar, change the sign (AND↔OR).

Absorption & Other Useful Rules

A + AB = A (Absorption) A(A+B) = A (Absorption) A + ĀB = A + B (Simplification) AB + ĀC + BC = AB + ĀC (Consensus — BC is redundant)

SOP and POS Forms

Standard SOP (Sum of Minterms)

Each minterm = product where ALL variables appear (complemented or not). Output = 1 for those rows.

F = Σm(2,3,5,6,7) means F=1 for minterms 2,3,5,6,7
Minterm 5 (101) → A·B̄·C
Minterm 6 (110) → A·B·C̄
SOP = ĀBC̄ + ĀBC + AB̄C + ABC̄ + ABC

Standard POS (Product of Maxterms)

Each maxterm = sum where ALL variables appear. Output = 0 for those rows.

F = ΠM(0,1,4) means F=0 for rows 0,1,4
Maxterm 0 (000) → A+B+C
Maxterm 1 (001) → A+B+C̄
Maxterm 4 (100) → Ā+B+C

Converting Between Minterm and Maxterm Notation

Rule: The minterms NOT in F's SOP are the maxterms of F's POS.
F = Σm(0,1,2,5,7) for 3 variables → F = ΠM(3,4,6)

Karnaugh Map (K-Map) Simplification ⭐

K-maps give the minimum SOP or POS without long algebra. The key is proper grouping.

K-map cell ordering (Gray code order)

3-Variable (2×4)4-Variable (4×4)
Rows: A | Cols: BC (00,01,11,10) Rows: AB (00,01,11,10) | Cols: CD (00,01,11,10)

Grouping Rules

  1. Groups must contain 1, 2, 4, 8, 16... cells (powers of 2).
  2. All cells in a group must contain 1s (for SOP) or 0s (for POS).
  3. Groups must be rectangular (including wrap-around at edges).
  4. Make groups as large as possible, and as few as possible.
  5. Every 1 must be covered by at least one group.
  6. Don't-care (×) cells can be included if they help enlarge a group.

Reading the Minimum SOP Term from a Group

Keep variables that are CONSTANT within the group. Drop variables that change.

Example: F(A,B,C) = Σm(0,1,2,5,6)

BC: 00 01 11 10
A=0: 1 1 0 1
A=1: 0 1 0 1

Group 1: m0,m1,m2 (top row, left 3) → B constant=0, C changes → Ā·B̄... actually: m0(00),m1(01) → A=0,B=0 → ĀB̄ Group 2: m1,m5 (col 01) → B=0,C=1,A changes → B̄C Group 3: m2,m6 (col 10) → B=1,C=0,A changes → BC̄
Min SOP = ĀB̄ + B̄C + BC̄

K-map POS Minimization

Group the 0s instead. Each group gives a sum term. Variables constant across the group appear (uncomplemented if they were 0, complemented if they were 1).

Don't-Care Terms

Strategy: Include don't-cares (×) in groups ONLY if they help create a larger group. Never leave them isolated as a single group.

Boolean Algebra Simplification Steps

  1. Write the Boolean expression for the circuit or truth table.
  2. Apply laws (factoring, absorption, DeMorgan's) to reduce terms.
  3. Use consensus: AB + ĀC + BC = AB + ĀC (remove BC).
  4. Verify with a truth table or K-map.
Example: F = AB + AC + ĀB̄C
= A(B+C) + ĀB̄C
= ... apply simplification ...
Use K-map for guaranteed minimum result.
CH 04

Combinational Logic Circuits

Combinational vs. Sequential

Combinational
  • Output depends ONLY on current inputs
  • No memory/storage
  • No feedback path
  • Examples: adders, encoders, decoders, MUX
Sequential
  • Output depends on current inputs AND past state
  • Has memory (flip-flops)
  • Examples: counters, registers, FSMs

Design Procedure for Combinational Circuits

  1. Logical Abstraction: Determine inputs, outputs, and assign logic values.
  2. Truth Table: Define output for every possible input combination.
  3. Boolean Expression: Write SOP or POS; simplify with K-map.
  4. Logic Diagram: Draw using available gates; verify correctness.

Encoders

Converts 2ⁿ inputs into an n-bit binary code. Only one input is active at a time.

4-to-2 Binary Encoder (Example)

4 inputs (S₀–S₃) → 2-bit output (D₁D₀). Active-LOW inputs (0 = pressed).

When S₀ active (0): D₁D₀ = 00
When S₁ active (0): D₁D₀ = 01
When S₂ active (0): D₁D₀ = 10
When S₃ active (0): D₁D₀ = 11

Logic (simplified with K-map):
D₀ = S̄₁·S̄₃ or simplified expression from K-map
D₁ = S̄₂·S̄₃ or simplified expression from K-map
INT₀ = S₀·S₁·S₂·S₃ (flag: 1 when any key pressed)

Multiplexers (MUX) & Demultiplexers (DEMUX)

4-to-1 MUX

  • 4 data inputs (D₀–D₃)
  • 2 select inputs (A₁, A₀)
  • 1 output Y
Y = Ā₁Ā₀D₀ + Ā₁A₀D₁ + A₁Ā₀D₂ + A₁A₀D₃

Select inputs route one data input to the output.

1-to-4 DEMUX

  • 1 data input
  • 2 select inputs
  • 4 outputs

Routes the single input to one of 4 outputs based on select. Reverse of MUX.

Note: A decoder with an enable = a DEMUX.

Analysis of Combinational Circuits

  1. Label all gate outputs with intermediate variables.
  2. Write Boolean expressions for each intermediate output, working forward from inputs to outputs.
  3. Simplify the final output expression using Boolean algebra or K-map.
  4. Build the truth table from the simplified expression.
  5. Determine the logic function (e.g., comparator, parity checker).
